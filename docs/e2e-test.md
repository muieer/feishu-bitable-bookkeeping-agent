# 记账 MVP 验收方法

本次验收覆盖「飞书消息 → 火山方舟 → 结构化与业务校验 → lark-cli 写入 → 飞书回复」，以及即时纠错、明确长期偏好和异常处理。正式系统提示词未准备好时，只进行离线和只读验证，不启动生产记账测试。

## 1. 本地与只读检查

在项目根目录执行：

```bash
source .venv/bin/activate
python -m pytest -q
ruff check src tests
ruff format --check src tests
bookkeeping-agent --check
bookkeeping-agent --check-remote
```

预期：离线检查通过；本地知识与表 ID 匹配；远端字段及完整分类选项通过校验。提示词为空时，本地检查明确显示 Agent 尚不能启动。

离线测试使用模拟模型决策、模拟 HTTP 和模拟 CLI 子进程，不修改真实账单。SDK、Pydantic AI、进程调用和 JSON 文件流程采用真实组件。模型语义与远端新增、修改权限仍需真实验收。

## 2. 准备提示词与会话

将正式提示词放入 `prompts/system.md`，或配置 `AGENT_SYSTEM_PROMPT_PATH`。接入合同见 [提示词说明](../prompts/README.md)。确认 CLI 身份对目标表具有新增及修改记录权限。

需要连续追问或即时纠错时，使用 `bookkeeping-agent --interactive` 或启动机器人长连接 `bookkeeping-agent`。单次 `--ask` 退出后会丢失短期会话，不能跨进程纠错。

以下真实测试会写入配置的表格。每笔新增后记录其 ID，核对消费日期、金额、描述和完整分类路径。不要仅凭回复文字判断远端数据正确。

## 3. 新增、分类和静默验收

| 输入 | 验收结果 |
| --- | --- |
| 今天外卖午饭 25 元 | 创建一条，日期为消息发送日期，分类「饮食 / 外卖」 |
| 昨天咖啡 18 元 | 创建一条，日期为消息发送时间在配置时区的前一天，分类「饮食 / 咖啡」 |
| 给母亲买咖啡 30 元 | 按个人用途规则分类为「人情往来 / 父母」 |
| 停车费 10 元 | 分类「交通通信 / 汽车 / 停车费」 |
| 今天午饭 25 元 | 根据现有个人规则追问堂食还是外卖，未回答前不写入 |
| 今天买了点东西 | 追问缺失内容、金额及必要分类信息，未回答前不写入 |
| 堂食（接在午饭追问后） | 合并上一轮事实，只创建一条原消费账单 |
| 咖啡 18 元，午饭外卖 25 元 | 提示分别发送，不只记一笔或合并金额 |
| 明天准备买咖啡 / 这个商品售价 18 元 / 查询消费 / 闲聊 | 无回复，无历史或写入 CLI 调用，数据无变化 |
| 图片、语音 | 忽略，不调用模型 |

确认历史检索仅在模型确有需要时进行；明确规则不能被历史案例覆盖。午饭示例的追问遵循现有规则，不能为满足「自动记账」示例而猜测用餐方式。

## 4. 纠错、偏好与隔离

| 操作 | 验收结果 |
| --- | --- |
| 新增后发送「不对，刚才是 28 元」 | 修改该用户、该会话最近账单金额，不创建新行 |
| 指出最近汽车消费实际是咖啡消费 | 合法分类修改后，原三级分类清空 |
| 另一用户或另一会话发送纠错 | 不能修改前一用户或前一会话账单 |
| 表格中手动修改最近账单后，再发送纠错 | 停止覆盖并提示核对 |
| 只纠正一次分类 | `preferences.json` 不新增长期偏好 |
| 以后豆浆都归类为食品 | 保存完整合法路径「饮食 / 食品」，不修改已有账单 |
| 随后发送「豆浆 5 元」 | 按新的明确偏好分类；重启后偏好仍有效 |
| 追问在午夜前发生，补充在午夜后发送 | 原消费日期不因回答跨日而改变 |
| 追问后另发一笔新消费 | 新账单采用新消息的发送日期 |

## 5. 去重与故障

消息 ID 相同的重投递应避免再次执行；人工重新发送相同文字具有新消息 ID，按新的消费处理，不等同于平台重投递。

离线测试已覆盖同一消息重复投递、回复失败后的重启、写入中取消、写入成功后本地日志失败，以及同一会话新增后纠错的顺序。真实故障测试应先检查目标与预期影响，再临时使用不可写的测试配置；不要通过重新发送生产消费验证是否写入。

| 场景 | 验收结果 |
| --- | --- |
| CLI 明确失败 | 不反馈记账成功 |
| 创建超时、异常返回、缺少唯一记录 ID | 提示核对，不自动重复创建 |
| 修改提交后尚未核对到完整结果 | 不宣称修改完成，提示核对 |
| 模型失败或理解阶段超时 | 安全错误回复，不执行写入 |
| 去重日志无法保存 | 不提交新写入 |
| 创建成功但飞书回复发送失败 | 保留成功日志，重投递不再次创建 |
| 应用重启 | 最近对话和纠错上下文丢失；已保存偏好和写入去重仍有效 |
