# 验证方法与验收范围

开发验证使用虚构分类知识、FunctionModel、MockTransport 和临时模拟 CLI。真实 LLM 调用、真实飞书消息与真实账本写入均为 0 次。离线验证检查结构与执行合同，不能证明真实模型在所有自然语言场景中的识别和分类准确性。

## 离线验证

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check src tests
.venv/bin/ruff format --check src tests
```

测试配置总发送预算为 0，并在自动夹具中阻断真实 HTTP 传输。HTTP 协议测试显式使用 MockTransport，表格测试使用临时模拟 CLI 子进程。Pydantic AI 结构解析、SDK 消息规范化、服务编排、字段校验、操作去重及日志使用实际实现。

## 核心覆盖

| 场景 | 验证行为 |
| --- | --- |
| 无消费 | 只识别一次，不调用第二阶段或 CLI，精确回复「此次不包含消费行为。」 |
| 两阶段输入 | 第一阶段无分类知识；第二阶段完整注入分类树和规则，只提供相关旧账单 |
| Schema 缺字段、额外字段、错误枚举与类型 | 拒绝；各阶段最多一次输出重试，无自由文本或模型业务工具 |
| 关联未知、其他用户或其他会话编号，重复关联 | 第一阶段拒绝，不分配新编号、不写入 |
| 改写原文、增删消费编号、new/update 行为冲突 | 第二阶段拒绝，不写入 |
| 相同原文真实出现两次 | 允许两笔；单一来源重复或重叠识别拒绝 |
| 新增、更新、澄清混合 | 逐笔处理，结果按规定分组，组内 B 编号数值升序 |
| 金额、日期或分类路径无效 | 执行失败独立展示，其他合法消费继续 |
| 修改金额 | 合并成功快照，保留未改字段，只提交变化金额 |
| 未写入编号更新 | 拒绝补写；澄清不存部分事实，新消费使用新编号 |
| 外部修改、记录读取异常或表结构变化 | 预检失败，不覆盖远端 |
| 新增/更新响应 ID 缺失、异常、字段被忽略 | 待核对，不推定成功、不自动重试 |
| 部分确认结果 | 保留已确认成功，剩余编号待核对 |
| 超时、取消、重投与重启 | 持久化保留阻止再次提交，已成功消息静默忽略 |
| 本地日志、去重文件或结果保存失败 | 写前阻断，写后保留已确认结果并提示 |
| 测试模式 | 仍校验，准备新增/更新，不写远端；去重与正式模式隔离 |
| 卡片 | 过程仅实时耗时，结束后分组结果；中间更新先结束，避免覆盖最终结果 |
| 反馈失败 | 卡片或文字回退不重复业务写入 |
| 请求预算 | 两阶段、输出重试、SDK 重试、跨客户端和重定向共享消息上限；持久化总预算不因重启重置 |

## 真实模型语义验收

本次开发未调用真实模型。后续语义验收应针对两阶段分别观察识别数量、关联、规范化、分类依据、日期及 update 的空值字段。重点场景包括商品明细与合计只算一笔、无标点多笔、相同消费不同时间、明确用途改变个人分类、分类冲突、单条消息独立消费不共享日期，以及只修改金额不重填其他字段。

一次开发任务的真实 LLM 总次数不得超过 10 次，包含两个阶段、输出重试、SDK 重试、失败发送与重定向。应为整个任务使用同一个持久化预算文件，已有计数继续累计，不删除或改写以绕过额度：

```bash
export LLM_MESSAGE_REQUEST_LIMIT=10
export LLM_HTTP_REQUEST_LIMIT=10
export LLM_HTTP_BUDGET_PATH=.runtime/semantic-verification-budget.json
```

单消息额度始终最多 10；总预算可进一步限制整个验收任务。若只验证语义，直接调用 `DecisionEngine.recognize` 和 `DecisionEngine.decide`，中间显式验证并分配编号，使用虚构上下文和 `message_request_scope`，不调用真实表格执行。`TEST_MODE=true` 仍调用模型和只读表格，不能代替离线模拟。

## 真实飞书验收范围

本次未进行真实飞书界面和远端读写验收。专用测试账本中应核对 Card 2.0 桌面及移动端效果、初始耗时、每秒刷新、排队顺序、最终分组、B 编号稳定性、纯文本长内容和异常提示。新增和更新按写入成功响应及准确记录 ID 确认，不做写后回读；不确定结果需人工核对。
