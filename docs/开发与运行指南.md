# 开发与运行指南

本项目在本地运行一个 Python 应用。用户通过飞书机器人发送完整文字消息，两阶段 Pydantic AI 调用火山方舟完成识别与决策，程序校验后通过 `lark-cli` 执行。行为合同见 [两阶段提示词说明](../prompts/README.md)，执行边界见 [系统架构与工作流程](系统架构与工作流程.md)。

## 安装与本地配置

需要 Python 3.11+、官方 `lark-cli`、支持 Function Calling 的火山方舟模型。依赖版本保留 `lark-channel-sdk==1.4.0`、`pydantic-ai-slim[openai]==2.54.0`。

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock.txt
```

在项目根目录运行。已有 `.env` 时只补充需要覆盖的配置；首次配置时复制 `.env.example`，填写真实机器人、模型与表格参数。分类文件未存在时复制三个 `knowledge/*.example.json` 模板，调整表 ID、字段名称、类型、分类选项和版本，使其与目标表一致。已有个人知识文件时保留内容，不用模板覆盖。

| 配置 | 用途与默认值 |
| --- | --- |
| `LARK_APP_ID`、`LARK_APP_SECRET` | 机器人凭证，必填 |
| `ARK_API_KEY`、`ARK_MODEL` | 方舟凭证与支持 Function Calling 的模型或接入点，必填 |
| `ARK_BASE_URL` | 默认 `https://ark.cn-beijing.volces.com/api/v3` |
| `BITABLE_BASE_TOKEN`、`BITABLE_TABLE_ID` | 目标 Base 与表 ID，必填，需匹配知识文件 |
| `BITABLE_DATE_FIELD`、`BITABLE_AMOUNT_FIELD`、`BITABLE_DESCRIPTION_FIELD` | 默认「记账日期」「金额」「具体」 |
| `BITABLE_CATEGORY1_FIELD`、`BITABLE_CATEGORY2_FIELD`、`BITABLE_CATEGORY3_FIELD` | 默认「一级分类」「二级分类」「三级分类」 |
| `RECOGNITION_PROMPT_PATH` | 默认 `prompts/recognition.md`，第一阶段提示词 |
| `DECISION_PROMPT_PATH` | 默认 `prompts/decision.md`，第二阶段提示词 |
| `CATEGORIES_PATH`、`RULES_PATH`、`SCHEMA_PATH` | 默认 `knowledge/categories.json`、`knowledge/rules.json`、`knowledge/schema.json` |
| `TEST_MODE` | 默认 false；true 时只准备新增/更新，仍调用模型和只读预检，不写远端记录 |
| `OPERATION_JOURNAL_PATH` | 默认 `.runtime/operations.json`，持久化消息与逐笔去重状态 |
| `CONTEXT_TTL_SECONDS` | 默认 1800 秒，窗口编号和已确认消费的空闲有效期 |
| `DISPLAY_TIMEZONE` | 默认 `Asia/Shanghai`，消息日期与表格日期时区 |
| `LARK_CLI_PATH`、`LARK_CLI_IDENTITY` | 默认 `lark-cli`、`user` |
| `CLI_TIMEOUT_SECONDS` | 默认 30 秒，每次 CLI 操作的超时 |
| `AGENT_TIMEOUT_SECONDS` | 默认 90 秒，两个阶段合计的理解超时；执行前生效 |
| `LLM_MESSAGE_REQUEST_LIMIT` | 默认 10，范围 1–10，单条消息实际 HTTP 发送预算 |
| `LLM_HTTP_REQUEST_LIMIT`、`LLM_HTTP_BUDGET_PATH` | 可选整个验证过程的持久化总预算；默认文件 `.runtime/llm-http-budget.json` |
| `LOG_FILE_PATH`、`MESSAGE_LOG_DIR` | 默认 `logs/service.log`、`logs`，总日志与逐消息日志目录 |
| `BITABLE_VIEW_ID` | 仅 `--query` 诊断使用；记账针对整张目标表 |

旧 `AGENT_SYSTEM_PROMPT_PATH`、`PREFERENCES_PATH` 和 `prompts/system.md` 已移除。已有 `.env` 中无需指定提示词路径时，可直接使用两阶段默认文件。修改提示词、配置或代码后重启服务。个人知识文件和 `.env` 不纳入 Git。

当前规则文件保留分类条件、路径、适用边界和信息不足的触发条件，不包含历史消费示例、样本数量或预设追问文案。清理前的实际规则与示例规则分别保存在 `knowledge/archive/rules.before-cleanup-20261012.json` 和 `knowledge/archive/rules.example.before-cleanup-20261012.json`，原始内容完整保留。程序只加载 `RULES_PATH` 指定的文件，不自动读取归档目录。个人规则及其归档继续由 Git 忽略，虚构示例归档纳入版本管理。

## 飞书与模型准备

飞书自建应用需要机器人能力、消息接收发送、卡片更新、表情回复及长连接事件订阅。沿用现有 Channel SDK 的 `im.message.receive_v1` 接入；卡片更新与表情权限分别使用 `im:message:update`、`im:message.reactions:write_only`。需要在飞书控制台发布版本使配置生效。

CLI 使用自身保存的登录态，与机器人凭证独立。运行用户应具备目标表的读取、新增和修改权限；应用不自动登录或切换身份。方舟使用 OpenAI 兼容的 Chat Completions 非流式接口，两个阶段以 Function Calling 返回结构化结果。

## 启动与检查

```bash
# 仅检查本地配置、分类知识和两个提示词，不调用模型或连接远端。
bookkeeping-agent --check

# 同时只读核对远端字段，不调用模型、不写账单。
bookkeeping-agent --check-remote

# 跳过模型，只读查询最近 N 条消费；不向机器人开放查询功能。
bookkeeping-agent --query 10

# 启动飞书机器人长连接。
bookkeeping-agent

# 在终端处理一条完整消息；正常模式会实际写入目标表。
bookkeeping-agent --ask '午餐堂食20元'

# 同一终端上下文中发送多条消息，可用 B 编号修改成功账单。
bookkeeping-agent --interactive
```

收到文字消息后立即回复 Card 2.0 卡片，并添加 `OneSecond` 表情。同一会话按接收顺序处理；排队和处理期间只显示从收到消息起累计的耗时，每秒尝试刷新。最终按新增、更新、澄清分组，失败和待核对单独展示。模型内部推理、处理阶段和执行明细不显示在卡片中。

卡片请求的应用级等待上限为 3 秒。最终更新失败时尝试完整卡片回退，再尝试文字回退。反馈失败不会重复写入。可捕获中断会尽力结束卡片；强制终止或网络完全不可用时可能保留最后一次显示状态。

## 日志、预算与排查

总日志同时输出到终端和文件；逐消息日志位于 `MESSAGE_LOG_DIR/messages/`，保留两阶段模型输入、Schema、输出、重试、实际 HTTP 通信、逐笔状态和 CLI 结果。凭证字段及已知密钥脱敏。处理阶段仅用于日志诊断。

模型发送边界强制限制单条消息最多 10 次实际 HTTP 请求；输出重试、SDK 自动重试和 HTTP 重定向均计入。可选总预算使用文件锁及原子保存，在客户端复用和进程重启后继续累计；设为 0 时阻止真实模型请求。

| 现象 | 检查与处理 |
| --- | --- |
| Agent 无法启动 | 检查两个提示词文件是否存在且非空，再运行 `--check` |
| 知识校验失败 | 核对分类树、规则和表 ID，检查完整父子路径、字段类型、单选选项与版本 |
| 模型输出不完整或格式不正确 | 在消息日志中分别检查 recognition、decision 的 Schema、输出和重试反馈；此时没有写入 |
| 请求预算耗尽 | 检查消息预算和总预算计数，保留计数，不重置文件绕过上限 |
| 更新目标被外部修改 | 在表格中核对目标；程序不覆盖外部变更 |
| 写入结果待核对 | 人工查看目标表；不要删除去重文件或重发消费试探结果 |
| 日志无法保存 | 检查日志目录和权限；新的模型调用与写入会停止，已提交操作继续确认 |
| 机器人没有回复 | 检查长连接、应用发布、权限和 `reply_failed`；非文字和已成功处理消息静默忽略 |

## 开发入口

| 模块 | 职责 |
| --- | --- |
| `models.py` | 两阶段输出 Schema、判别决策联合与完整账单 |
| `agent.py` | 两个 Agent、独立提示词、运行上下文及输出约束 |
| `service.py` | 两阶段编排、逐笔校验、预检、执行与确认 |
| `state.py` | 窗口编号、远端映射、成功快照与分组反馈 |
| `knowledge.py` | 完整个人分类知识、分类路径和表结构校验 |
| `tools.py` | 固定 CLI 命令、异步调用、超时清理与响应确认 |
| `request_budget.py`、`agent_tracing.py` | 单消息与持久化总发送预算、模型通信观察 |
| `progress.py`、`feedback.py`、`channel.py` | 耗时卡片、送达回退与 Channel SDK 消息通道 |
| `storage.py`、`tracing.py` | 原子去重状态、完整消息日志与落盘边界 |

验证入口与真实模型验收限制见 [验证方法](e2e-test.md)。
